# 백그라운드 실행과 iOS 제한 사항

이 문서는 SwiftProxy가 iOS에서 **할 수 있는 것과 없는 것**을 구분해 정리합니다.
"확인됨"은 Apple 공식 문서 또는 이 저장소의 자동 테스트로 확인한 내용,
"추정"은 실기기에서 검증하지 않은 내용입니다.

## 1. 일반 앱의 백그라운드 실행

- iOS는 백그라운드로 간 앱을 짧은 유예 시간 뒤 **일시 중지(suspend)** 합니다. 일시 중지된 앱은 CPU 시간을 받지 못하므로 들어오는 연결을 받거나 데이터를 중계할 수 없습니다. (확인됨: iOS 앱 생명주기)
- 프록시 서버를 무기한 백그라운드에서 돌리는 공개 API는 없습니다. VPN 앱이 쓰는 Network Extension(Packet Tunnel)은 별도 entitlement와 다른 구조가 필요하며 이 앱은 쓰지 않습니다.
- SwiftProxy는 백그라운드 작업 없이 백그라운드로 가면 `beginBackgroundTask` 유예 시간 동안만 실행하고, 유예가 끝나기 직전에 **서버를 정상 종료**합니다. 일시 중지 상태에서 리스너만 열려 있는 "좀비" 상태를 피하기 위해서입니다.

## 2. BGContinuedProcessingTask (iOS 26)

확인됨 (Apple 문서 "Performing long-running tasks on iOS and iPadOS"):
- 포그라운드에서, **사용자 동작(버튼 탭)에 대한 응답으로만** 제출할 수 있습니다.
- 시스템이 작업 진행 상황을 **시스템 Live Activity**로 표시하고, 사용자는 거기서 작업을 취소할 수 있습니다.
- 앱은 `progress`로 진행률을 보고해야 합니다. 시스템은 진행이 멈춘 것처럼 보이는 작업을 사용자에게 취소 후보로 보여 주고, 자원이 부족하면 **진행이 적은 작업부터 종료**합니다.
- 사용자가 취소하면 `expirationHandler`가 호출됩니다.
- **앱 스위처에서 앱을 닫으면 작업이 취소되며, 앱은 그 사실을 통보받지 못합니다.**

이 앱의 사용 방식:
- 시작 버튼을 누르면 `com.taegun.swiftproxy.proxy.<UUID>` 식별자로 작업을 등록·제출합니다 (`strategy = .fail`: 바로 시작할 수 없으면 대기열에 넣지 않고 실패).
- **앱 쪽 시간 제한은 없습니다.** 프록시에는 "완료율"이 없으므로 5초마다 heartbeat로 `completedUnitCount`를 올리고 `totalUnitCount`를 그보다 1 크게 유지합니다. 부제목에는 연결 수·속도·실행 시간을 표시합니다.
- 사용자가 중지하면 `setTaskCompleted(success: true)`, 시스템/사용자가 만료시키면 서버를 정리한 뒤 `setTaskCompleted(success: false)`를 호출합니다.

비판적 검토:
- 이 API는 끝이 있는 작업(동영상 내보내기 등)을 위해 설계되었습니다. 끝이 없는 서비스에 heartbeat 진행률을 붙이는 것은 API 의도와 다른 사용이며, **시스템이 얼마나 오래 허용하는지는 문서화되어 있지 않습니다.** (추정: 기기 상태·배터리·발열에 따라 달라질 것)
- 따라서 "무기한 실행"은 보장되지 않습니다. 시스템이 작업을 끝내면 서버도 멈춥니다.
- 진행률을 끝없이 늘리는 방식에 대해 시스템 UI가 어떻게 표시하는지(퍼센트 등)는 **실기기 미확인**입니다.

## 3. Live Activity와 실제 프로세스

- Live Activity는 **표시 수단일 뿐 프로세스를 살려 두지 않습니다.** 앱이 일시 중지되거나 종료돼도 Live Activity는 화면에 남을 수 있습니다.
- 그래서 모든 갱신에 45초 후의 `staleDate`를 붙입니다. 앱이 갱신을 멈추면 위젯이 "확인 불가"로 바뀝니다.
- 서버를 중지하면 Live Activity를 즉시 종료하고, 다음 실행 때 남아 있는 Live Activity도 정리합니다.
- BGContinuedProcessingTask의 시스템 Live Activity와 앱 자체 Live Activity가 **동시에 두 개** 보일 수 있습니다. 앱 자체 Live Activity는 설정에서 끌 수 있습니다.
- 갱신 간격은 최소 5초이며, 내용이 같으면 생략합니다.

## 4. NWListener / NWConnection과 백그라운드

- 프로세스가 실행 중(포그라운드 또는 BGContinuedProcessingTask 실행 중)이면 리스너와 연결은 정상 동작해야 합니다. (추정: 백그라운드 상태에서의 수신은 실기기 미검증)
- 프로세스가 일시 중지되면 기존 TCP 연결은 응답하지 않게 되고, 클라이언트 쪽에서 시간 초과가 납니다.

## 5. 앱 강제 종료·메모리 압박

- 앱 스위처에서 종료하거나 메모리 부족으로 시스템이 프로세스를 없애면 앱은 아무 코드도 실행하지 못합니다.
- SwiftProxy는 시작 시 "세션 실행 중" 표시를 저장하고 정상 중지 때 지웁니다. 다음 실행에서 표시가 남아 있으면 **비정상 종료로 추정**해 대시보드에 안내합니다. 원인(강제 종료/시스템 종료/크래시)은 구분할 수 없습니다.

## 6. 네트워크 변경

- `NWPathMonitor`로 기본 경로와 셀룰러 경로를 감시하고, 변경 시 접속 주소를 다시 계산합니다.
- Wi-Fi가 끊기면 다른 기기가 접속할 주소가 사라집니다. 이미 중계 중인 연결은 대상 쪽 경로가 바뀌면 끊길 수 있으며, 자동 재연결은 하지 않습니다 (TCP 특성상 불가).
- 셀룰러 강제: "셀룰러만" 설정 시 대상 서버로 나가는 연결에 `requiredInterfaceType = .cellular`를 적용합니다. **이 앱이 만드는 연결에만 적용**되며 iPhone 전체 트래픽 경로를 바꿀 수는 없습니다. 통신사의 테더링 정책과의 관계는 확인하지 않았습니다. (실기기 미검증)
- 리스너는 셀룰러 인터페이스를 제외하므로 셀룰러 IP로 들어오는 외부 접속은 받지 않습니다.

## 7. 지원하지 않는 기능

- SOCKS5 BIND, UDP ASSOCIATE (reply 0x07)
- SOCKS4/4a
- HTTP/2 프록시, HTTPS 프록시(프록시 자체를 TLS로 감싸기)
- HTTP 포워드 프록시의 keep-alive 재사용 (요청마다 `Connection: close`)
- DNS 서버 (참고 프로젝트에는 있으나 이 앱은 제공하지 않음)
